# نقشه intent و URL canonical

این سند تصمیم نهایی معماری URL است؛ تحلیل بازار در `seo-intent-competitor-map.md` ثبت شده است.

| intent | URL مالک | نوع صفحه | URLهای ممنوع/ادغام‌شونده |
|---|---|---|---|
| شناخت مقصد | `/destinations/{country}/{city}` | DESTINATION | صفحات جدا برای «دیدنی‌ها/آب‌وهوا» بدون محتوای مستقل |
| پرواز یک مسیر | `/flights/{origin}-to-{destination}` | FLIGHT_ROUTE | query، ترتیب واژگان جایگزین و synonym page |
| انتخاب هتل در شهر | `/hotels/{city}` | HOTEL_CITY | صفحات فیلتر ستاره/محله/قیمت |
| مقایسه تور مقصد | `/tours/{destination}` | TOUR_DESTINATION | تاریخ حرکت و پکیج نمایشی به‌عنوان landing |
| راهنمای فرودگاه | `/airports/{iata}` | AIRPORT_GUIDE | صفحات جدا برای هر ترمینال بدون نیاز مستقل |
| مقاله آموزشی | `/blog/{slug}` | BLOG_ARTICLE | نسخه چاپ، tag کم‌محتوا و URL تاریخ‌دار |
| جست‌وجو و تراکنش | `/flights/search` و مشابه | noindex | هر ترکیب query در sitemap |
| ویزا | `/visa/{country}` | VISA_COUNTRY | فعلاً noindex تا منبع و نگهداری عملیاتی کامل |

## قواعد جلوگیری از cannibalization

- هر intent فقط یک canonical دارد؛ synonymها محتوا یا URL تازه تولید نمی‌کنند.
- صفحات مقصد به پرسش عمومی پاسخ می‌دهند؛ مسیر پرواز فقط تصمیم‌های مربوط به همان مسیر را پوشش می‌دهد.
- هتل‌شهر درباره انتخاب محله و اقامت است و موجودی تجاری را جعل نمی‌کند.
- مقاله باید زاویه آموزشی مستقل داشته باشد و خلاصه صفحه مقصد نباشد.
- پارامترهای sort/filter/date/passenger هرگز canonical یا sitemap مستقل ندارند.

## پیوند داخلی پایه

مقصد ← مسیر پرواز + هتل‌شهر؛ مسیر ← مقصد + هتل + مسیر مرتبط؛ تور ← مقصد + مسیر؛ فرودگاه ← مقصد + مسیرهای مرتبط؛ مقاله ← مقصد + آرشیو مجله. هر صفحه indexable حداقل دو لینک زمینه‌ای دارد.
